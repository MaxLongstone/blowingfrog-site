5. What Opus 5.5 can and cannot do here

Where it is strong
  • Long autonomous runs. Built for long-running agentic coding, with a 1M-token context and 128K output. The whole project fits in its head.
  • Drives Unreal directly. Through MCP it spawns actors, builds materials, sets lighting, runs automation tests and reads what happened.
  • Sees the result. It takes text and images in, so it can look at a viewport screenshot and critique its own work.
  • Effort dial. Adaptive thinking is always on; you steer depth with effort to control cost and latency.
  • Priced to iterate. $4 in, $20 out per million tokens, with cheap cache reads.
Where it needs help
  • It does not make art. Text and images in, text out. Models, textures and audio come from other tools and from you.
  • Messy Blueprints. Developers report tangled node graphs. Plan: C++ and Python for logic, Blueprints only for tuning.
  • Vague direction fails. It works best with clear architecture and a tight scope. That is what phase 0 is for.
  • Official MCP is experimental. Epic warns the API can change and it is not for production. Localhost only, no authentication.
  • Feel needs a human. It can test that the buzzer fires, not that the tremor feels fair. That is your job.

7. Decisions

DecisionAnswerWhy
Connection to the web runUnreal, streamed into the page (Pixel Streaming). It sits in the site as another hidden level and the same page later loads inside the app.Unreal Engine dropped browser export after 4.24, so streaming is the only way to show real Unreal in a web page. The hidden level is rare, so the server bill stays tiny. The result goes back to the game through the page itself, so no return code is needed.
Frog modelHybrid: AI-generate the frog skin and each organ as separate pieces, then clean up in Blender and finish the materials in Unreal.Operation needs a hollow body, loose organs and collision shapes. One AI mesh has none of that.
LookStylized felt-and-clay, not photoreal.Matches the 2D game, suits comic gross-out, and hides AI mesh flaws.

Known risk: streaming adds roughly 50 to 100 ms of delay, which matters for a steady-hand game. The design absorbs it: the tremor is part of the fun and contact is judged on the server. Fallback if it bites: a lighter web-native version of the same operation.
